# 前端构建与部署说明

本文说明前端1的生产构建、同源部署和冒烟检查流程。前端生产环境统一使用 `/api` 访问 Drogon 接口，构建产物由 `server/config.json` 中的 `document_root` 托管。

## 1. 前端生产构建

在项目根目录执行：

```powershell
Set-Location web
npm ci
npm run build
npm run verify:dist
```

通过标准：

- `vue-tsc --noEmit` 无类型错误；
- Vite 成功生成 `web/dist/index.html` 与带哈希的 JS/CSS 资源；
- `verify:dist` 输出“生产构建检查通过”；
- `web/dist` 不提交到 Git，由交付环境现场构建。

## 2. 服务端准备

服务端负责人完成 Drogon 与 CMake 配置后，在项目根目录构建：

```powershell
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Release
```

预期程序为 `build/Release/dir_tree_server.exe`。服务端启动时工作目录应为 `server/`，从而使 `server/config.json` 中的 `../web/dist` 正确指向前端产物。

## 3. 一键启动

前端和服务端均准备好后，在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-release.ps1
```

若前端已经构建，可使用：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-release.ps1 -SkipFrontendBuild
```

启动后访问 `http://127.0.0.1:8080`。生产环境不需要单独运行 Vite，也不需要用户安装前端运行时。

## 4. 冒烟检查

服务启动后执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/smoke-check.ps1
```

脚本检查 `/`、`/tree`、`/search`、`/stats` 是否均返回 Vue 入口页面，用于验证同源托管和前端路由刷新。若任一路由返回 404，需要服务端负责人补充 SPA history fallback：未命中静态文件且不是 `/api/*` 时返回 `web/dist/index.html`。

## 5. 人工验收清单

- [ ] 访客可进入目录、查找、统计页面，但看不到用户管理和 P2 菜单；
- [ ] 普通用户登录、退出和修改密码可用；
- [ ] 管理员可进入用户管理、Merkle 和环检测页面；
- [ ] token 失效后清除本地登录态并返回登录页；
- [ ] 用户列表搜索、分页、启停、重置密码和角色变更可用；
- [ ] 直接刷新 `/tree`、`/search`、`/stats` 不返回 404；
- [ ] 浏览器控制台无未处理错误，网络面板无未登记的 4xx/5xx。

其中认证、用户管理、P2 与 `/api/*` 检查必须在对应后端控制器完成后执行；检查结果应登记到 T-43 联调记录，由测试成员执行 T-44 与 T-46 回归。
